# 사용성 테스트(UT) 진행 가이드 — 장면 F0~F4 기준

> 흐름과 화면 문구는 `docs/user-flows.md`를 기준으로 한다. 앱 기준일은 2026-10-31(토), 주인공은 김소연이다.

## 달라진 점

- 예전 앱 안 UT 모드(`?ut=1`, 진행자 패널, CSV 자동 기록)는 개편 때 main에서 빠졌다. 옛 구조로 만든 PR #35는 UT 전용이며 머지하지 않는다.
- 그래서 **진행자가 직접 관찰하고 기록한다.** 아래 기록표를 복사해서 쓴다.
- 캘린더 월뷰에는 "복원 N일 / 전체"와 복원 3상태(진한·옅은·회색)가 없다. 예전 과제 "회색 날짜 찾기"는 더 이상 진행할 수 없어 뺐다.
- 하단 탭은 캘린더 · 홈 · 리포트 3개다. 지도·앨범은 탭이 아니라 홈 카드에서 연다.

## 준비

| 항목 | 내용 |
|---|---|
| 기기 | 참가자 폰에서 Vercel 프리뷰 주소를 연다. 노트북이면 `pnpm dev` 후 브라우저를 375px 폭으로 맞춘다 |
| 데이터 | 전부 목업이다(주인공 김소연, 2026년 10~11월). 참가자의 실제 정보는 입력받지 않는다. 1단계 본인인증에는 진행자가 정한 가짜 값(이름 김소연, 000101-4, 010-0000-0000, 인증번호 아무 6자리)을 쓰게 하고, 닉네임은 아무 값이나 넣게 한다 |
| 초기화 | 앱은 상태를 저장하지 않는다. **새로고침하면 온보딩 1단계부터 다시 시작**한다. 참가자마다 새로고침한다 |
| 역할 | 진행자 1명(상황 읽기·시간 재기), 기록자 1명(탭·멈춤·발화 기록) |
| 시작 위치 | 온보딩을 마치면 홈에서 시작한다. 홈의 오늘은 10월 31일이다 |

## 진행 순서

1. 안내: "앱을 평가하는 게 아니라 앱이 쉬운지 보는 자리예요. 생각나는 걸 소리 내어 말해 주세요."
2. 온보딩은 참가자가 직접 진행한다(과제 1·2가 온보딩 안에 있다).
3. 과제마다 상황 카드를 읽어 주고 "시작"이라고 말한 순간부터 시간을 잰다.
4. 참가자가 "다 했어요"라고 하거나 성공 지점에 닿으면 멈춘다. 3분이 넘거나 참가자가 원하면 포기로 기록하고 다음 과제로 간다.
5. 과제마다 난이도(1 매우 쉬움 ~ 5 매우 어려움)를 묻는다.
6. 도움 요청에는 "어디를 눌러 보고 싶으세요?"처럼 되묻고, 정답 위치는 알려 주지 않는다.

## 과제

| 순서 | 장면 | 참가자에게 주는 상황 | 성공 지점 | 관찰 포인트 |
|---|---|---|---|---|
| 1 | F0-2 | 사진은 꼭 필요한 것만 쓰게 하고 싶어요. 앱을 시작하면서 설정해 보세요 | 개인정보 고지에서 갤러리 사용 범위를 읽고 "동의하고 계속"(거절도 성공) | 사용 범위 문구("±30분 · 반경 500m")를 읽는지, "동의 안 함"을 찾는지, 거절 뒤 불안해하는지 |
| 2 | F0-3 | 카드 결제내역을 불러오려고 해요. 꼭 필요한 약관에만 동의하고 진행해 보세요 | 필수 3개만 체크(선택은 비움) → "결제내역을 불러왔어요" | "전체 동의"부터 누르는지, (필수)/(선택) 표시를 읽는지, ⌄로 내용을 펼쳐 보는지 |
| 3 | F1-2·F1-4 | 오늘(10/31) 낮에 쓴 "카카오모빌리티"와 "(주)포토이즘코리아"가 뭐였는지 확인하고, 맞으면 확인해 주세요 | 두 결제 카드에서 복원된 문구(택시 탑승·포토이즘 강남역점)를 말하고 "맞아요" | 홈 "오늘 지출"에서 결제를 누르는지, 원본(작은 글씨)과 복원 결과를 구분하는지, 근거를 읽는지 |
| 4 | F2-1~F2-4 | 오늘 저녁 고깃집은 동기 4명과 먹고 내가 냈어요. 내가 실제로 쓴 돈으로 정리해 주세요 | 정산 결과 "내가 실제로 쓴 돈 30,000원" | 홈 알림 "그룹 결제가 감지됐어요"를 찾는지, 근거(입금 3건·일정 인원)를 읽는지, 결과 숫자를 이해하는지 |
| 5 | F2-5~F2-7 | 어제(10/30) 밤 "김지은 18,000원"을 보냈는데 뭐였는지 기억이 안 나요. 앱에서 확인해 보세요 | "링키가 찾았어요"에서 "맞아요" → 10/30 카드가 "식비로 재분류" | 알림을 찾는지, "연남동에서 지은님과 먹은 파스타"를 자기 기억과 맞춰 보는지, 맞아요/아니에요를 고르는 근거 |
| 6 | F1-6 | 10/30 낮 "(주)샐러디 선릉점"에는 기록이 없어요. 앨범에서 사진을 붙여 보세요 | 날짜 상세에서 "앨범에서 불러오기" → 사진 선택 → "불러오기" 후 카드가 "수정" 상태로 바뀜 | "앨범에서 불러오기"를 찾는지, 어느 결제에 붙이는 창인지 이해하는지 |
| 7 | F1-5 | 오늘 어디를 다녔는지 지도로 보고, 결제 핀을 하나 열어 보세요 | 홈 "지도로 보기" → 결제 핀 확인 | 핀의 "결제 당시 내 위치"를 **상점 위치로 오해하는지**, 사진 핀과 결제 핀을 구분하는지 |
| 8 | F4-3 | 다음 주에 약속이 있는지 확인해 주세요 | 리포트 탭 "다음 주 예고"에서 일정 읽기 | 리포트 탭을 찾는지, "예고"를 평가·조언으로 받아들이는지 |
| 9 | F3-4 | 10~11월에 성수에서 쓴 돈을 찾아보세요 | "성수에서 쓴 돈" 검색 결과 | 검색 진입점(돋보기)을 찾는지, 어떤 말로 검색하는지(그대로 기록) |

### 과제 준비 상태 (2026-10-06 기준)

| 과제 | 상태 | 비고 |
|---|---|---|
| 1~9 | 모두 지금 가능 | 장면이 `main`에 구현됨 |
| 4, 5 | 순서 주의 | 4를 끝내면 홈 알림이 사라지고, 5를 끝내면 "링키가 찾았어요" 알림이 사라진다. 한 번 한 과제는 새로고침하기 전에는 다시 못 한다 |
| 4 | 변형 | 알림에서 "아니요, 개인 지출"을 누르면 알림이 사라지고 정산 흐름을 못 본다. 참가자가 눌렀다면 그대로 기록하고 새로고침 후 다시 안내한다 |

## 마치고 묻는 질문

유도하지 않게 열린 질문으로 묻는다.

1. 결제 옆에 붙은 위치·일정·사진은 무엇이라고 생각했나요?
2. "링키가 찾았어요"에서 보여 준 근거를 보고 어떤 생각이 들었나요?
3. 지도의 결제 핀은 어디를 가리킨다고 생각했나요?
4. "기록 없음"이라고 적힌 곳을 봤을 때 어떤 느낌이었나요?
5. 사진·위치를 쓰는 범위를 설명한 화면에서 기억나는 게 있나요?
6. 리포트의 "다음 주 예고"는 어떤 도움이 된다고 느꼈나요?
7. 이 앱에서 다시 쓰고 싶은 기능과 쓰고 싶지 않은 기능은요?

## 문구·규칙 점검 (진행 중 같이 본다)

- [ ] 지도 결제 핀이 "결제 당시 내 위치"로 이해되는가 (상점 위치로 오해하지 않는가)
- [ ] "기록 없음"을 오류로 받아들이지 않는가
- [ ] "링키가 찾았어요"의 추정 문장을 근거 없이 믿거나, 반대로 의심하지 않는가 (근거 3줄을 읽었는지)
- [ ] 앱이 기분·의도를 짐작한다고 느낀 문장이 있었는가 (있으면 문장을 그대로 적는다)
- [ ] 평가받는다고 느낀 문장이 있었는가 (특히 리포트)
- [ ] 눌렀는데 아무 일도 없던 버튼이 있었는가 (있으면 화면과 위치를 적는다)

## 주의

- 참가자에게 실제 결제·사진·위치 정보를 요구하지 않는다. 화면에 보이는 정보는 모두 가상의 인물이다.
- 기록표와 녹음은 팀 공유 폴더에만 두고, 참가자 이름 대신 P번호를 쓴다.
- 과제 3~5는 서로 상태를 공유한다(확정한 결제, 처리한 알림). 과제 순서는 표 순서대로 둔다.
