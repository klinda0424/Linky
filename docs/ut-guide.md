# 사용성 테스트(UT) 진행 가이드 — 장면 F0~F4 기준

> 흐름과 화면 문구는 `docs/user-flows.md`를 기준으로 한다. 앱 기준일은 2026-10-31(토), 주인공은 김소연이다.
> 참가자에게 나눠 주는 배포용 자료는 `docs/ut-participant-kit.md`다. 이 문서는 **진행자·분석자용**이다.

## 달라진 점 (2026-10-08 갱신)

- 예전 앱 안 UT 모드(`?ut=1`, 진행자 패널, CSV 자동 기록)는 개편 때 main에서 빠졌다. 옛 구조로 만든 PR #35는 UT 전용이며 머지하지 않는다. 그래서 **진행자가 직접 관찰하고 기록하거나, 참가자가 배포용 자료의 자가 기록표를 채운다.**
- **정산 흐름이 바텀시트 하나로 바뀌었다.** 홈 알림 → "그룹 지출 같아요" 시트 → 그룹 결제 확인 → 정산 결과 → "정산 완료"가 한 시트 안에서 이어진다. 정산 대기함·정산표·정산 확정 화면은 없다. "인원 수정"은 -/+로 인원만 조절하는 시트 단계다(시트 안에서만 보이는 목업).
- **송금은 맞아요를 누르면 이름이 맥락으로 바뀐다.** "김지은 송금"이 "지은이랑 연남동 저녁"이 되고 원본 이름은 작은 글씨로 남는다. 홈 알림에서 눌러도, 카드에서 눌러도 같다.
- **홈 오늘 지출의 결제를 누르면 "지출 내역" 한 화면**이 열린다. 원본 가맹점명(위), 복원된 이름, 금액, [맞아요][수정], 일시·분류·결제 장소·연결된 기록이 한 화면에 있다. 홈 목록에는 복원된 이름만 보이고 원본은 이 화면에서 본다.
- **지도는 바텀시트("동선 지도")로 열린다.** 홈 "오늘의 동선 > 지도로 보기"에서 연다.
- **정산 내역은 리포트 탭 상단 "정산함"에서 연다.** 완료된 정산은 "✓ 완료"만 보이고 눌러서 들어가는 화면은 없다.
- 캘린더 월뷰에는 "복원 N일 / 전체"와 복원 3상태(진한·옅은·회색)가 없다. 예전 과제 "회색 날짜 찾기"는 뺐다.
- 하단 탭은 캘린더 · 홈 · 리포트 3개다. 지도·앨범은 탭이 아니라 홈 카드에서 연다.

| 역할 | 진행자 1명(상황 읽기·시간 재기), 기록자 1명(탭·멈춤·발화 기록) |

### 배포 주소

- 참가자에게 줄 주소는 **최신 main이 반영된 주소**여야 한다. 일일 배포 한도(Vercel)나 크레딧(Netlify) 때문에 프로덕션 주소가 최신이 아닐 수 있으니, **배포 전에 아래 "배포 전 점검"의 1~3을 직접 해 본다.**
- 현재 배포용 주소: `https://linky-ahya0q6dg-klinda0424s-projects.vercel.app` (main `8ba3eb9`의 Vercel 프로덕션 개별 배포 주소). 이 주소는 바뀌지 않아 테스트 중 main에 머지가 들어가도 참가자 화면이 같다. 참가자 안내서(`docs/ut-participant-kit.md`)에 이미 넣어 두었다.
- 별칭 `https://linky-klinda0424s-projects.vercel.app`은 항상 최신 main을 가리키므로 테스트 기간에는 쓰지 않는다. Netlify 주소는 팀 로그인이 필요해 참가자용으로 쓸 수 없다.
- 앱을 고쳐 다시 배포하면 새 주소가 생긴다. 참가자를 중간에 바꾸지 말고, 바꿔야 하면 안내서의 주소를 교체한 뒤 새 참가자부터 쓴다.

### 배포 전 점검 (진행자가 5분 안에)

1. 배포 주소를 폰에서 열어 온보딩 1단계가 보이는지 확인한다.
2. 온보딩 하단 "개발자용 · 온보딩 건너뛰기"로 홈에 들어가 홈 알림 2개("링키가 찾았어요", "그룹 지출 같아요")가 보이는지 확인한다.
3. 홈 알림 "그룹 지출 같아요"를 눌러 시트가 올라오고 "정산 완료"까지 이어지는지 확인한다(최신 정산 흐름 여부 확인). 시트 대신 전체 화면이나 정산표가 뜨면 **옛 배포본**이므로 주소를 바꾼다.
4. 새로고침해서 초기 상태로 되돌린다.

## 진행 순서

1. 안내: "앱을 평가하는 게 아니라 앱이 쉬운지 보는 자리예요. 생각나는 걸 소리 내어 말해 주세요."
2. 온보딩은 참가자가 직접 진행한다(과제 1·2가 온보딩 안에 있다).
3. 과제마다 상황 카드를 읽어 주고 "시작"이라고 말한 순간부터 시간을 잰다.
4. 참가자가 "다 했어요"라고 하거나 성공 지점에 닿으면 멈춘다. 3분이 넘거나 참가자가 원하면 포기로 기록하고 다음 과제로 간다.
5. 과제마다 난이도(1 매우 쉬움 ~ 5 매우 어려움)를 묻는다.
6. 도움 요청에는 "어디를 눌러 보고 싶으세요?"처럼 되묻고, 정답 위치는 알려 주지 않는다.

## 마치고 묻는 질문

유도하지 않게 열린 질문으로 묻는다.

1. 결제 옆에 붙은 위치·일정·사진은 무엇이라고 생각했나요?
2. "링키가 찾았어요"에서 보여 준 근거를 보고 어떤 생각이 들었나요?
3. 송금 이름이 "지은이랑 연남동 저녁"으로 바뀐 것을 어떻게 느꼈나요? (바뀐 걸 알아챘나요? 어디서 온 이름이라고 생각했나요?)
4. 그룹 지출을 정산할 때 화면이 한 장씩 올라오는 방식은 어땠나요? 어느 단계에서 가장 헷갈렸나요?
5. 정산 결과의 "결제 총액 → 내가 실제로 쓴 돈"은 무슨 뜻이라고 이해했나요?
6. 지도의 결제 핀은 어디를 가리킨다고 생각했나요?
7. "기록 없음"이라고 적힌 곳을 봤을 때 어떤 느낌이었나요?

9. 리포트의 "다음 주 예고"는 어떤 도움이 된다고 느꼈나요?
10. 이 앱에서 다시 쓰고 싶은 기능과 쓰고 싶지 않은 기능은요?

## 문구·규칙 점검 (진행 중 같이 본다)

- [ ] 지도 결제 핀이 "결제 당시 내 위치"로 이해되는가 (상점 위치로 오해하지 않는가)
- [ ] "기록 없음"을 오류로 받아들이지 않는가
- [ ] "링키가 찾았어요"의 추정 문장을 근거 없이 믿거나, 반대로 의심하지 않는가 (근거 3줄을 읽었는지)
- [ ] 송금 이름이 바뀐 것(맥락 복원)을 "앱이 멋대로 지어낸 이름"으로 느끼지 않는가, 원본 이름이 남아 있는 것을 알아채는가
- [ ] 정산 시트 3단계에서 어느 단계를 "끝"으로 착각하는가 (예: 결과를 보고 시트를 닫아 "정산 완료"를 안 누름)
- [ ] 앱이 기분·의도를 짐작한다고 느낀 문장이 있었는가 (있으면 문장을 그대로 적는다)
- [ ] 평가받는다고 느낀 문장이 있었는가 (특히 리포트)
- [ ] 눌렀는데 아무 일도 없던 버튼이 있었는가 (있으면 화면과 위치를 적는다)

## 주의

- 참가자에게 실제 결제·사진·위치 정보를 요구하지 않는다. 화면에 보이는 정보는 모두 가상의 인물이다.
- 기록표와 녹음은 팀 공유 폴더에만 두고, 참가자 이름 대신 P번호를 쓴다.
- 과제 3~5, 8은 서로 상태를 공유한다(확정한 결제, 처리한 알림). 과제 순서는 표 순서대로 둔다.
- 시트 바깥 어두운 영역을 누르면 시트가 닫히고 정산이 취소된다. 참가자가 그렇게 닫았다면 알림이 남아 있으니 다시 열게 안내하고 메모에 적는다.
